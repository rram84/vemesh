
\page tutorial_element_agglomeration Element agglomeration

This tutorial demonstrates using vemesh to agglomerate faces to improve element qualities in a polygonal mesh.  
Element agglomeration merges neighboring faces in a mesh when
favorable. Specifically, if \f$f,g\f$ are agglomerable neighbors with
qualities \f$Q(f)\f$ and \f$Q(g)\f$, respectively. Then the
agglomerated face \f$fg\f$ is considered feasible only of \f$Q(fg)>{\rm qfactor}\times \min\{Q(f),Q(g)\}\f$.  
The metric used to evaluate face qualities is supplied by the user.  
Agglomeration changes the topology of the mesh, but leaves the count
and locations of the mesh vertices unchanged.


**Overview:**  
- Load a polygonal mesh with domain labels.
- Choose a face-based quality metric and a quality threshold.
- Identify low-quality faces whose quality falls below the prescribed threshold.
- For each candidate face, select an agglomerable neighbor that maximizes quality improvement.
- Merge neighboring faces only if the agglomerated face satisfies the improvement criterion.
- Update the mesh topology while preserving vertex locations.
- Output the agglomerated mesh and compare input/output face quality  vectors.

## Explanation

### Load the mesh
```cpp
const std::string meshfile = "sample_data/sorgente/mesh3_20.off";
... 
pmp::SurfaceMesh in_mesh = vm::read_off(meshfile);

```
vemesh provides readers for OFF and VTK file formats, see @ref io.  
The mesh loaded this way has 
- an integer-valued face property `domain_id`, initialized to a default value of 1.
- an integer-valued vertex property `interface_id`, initialized to a default value of -1.

Faces can be merged only with an *agglomerable* neighbor. In
particular, agglomeration ensures that:
- only faces with the same `domain_id` can be merged.
- all vertices in the mesh belong to an edge, i.e., no *isolated*
vertices are created.  
The condition of identical domain ids ensures that if a mesh conforms
 to an embedded interface so that faces on either side of the
 interface are assigned different domain ids, then the agglomerated
 mesh conforms to the interface as well and assigns consistent
 `domain_ids` to agglomerated faces.  

The `domain_id` can be accessed as:
```cpp
  auto& domain_ids = in_mesh.get_face_property<int>("domain_id"); 
```
and can be modified as:
```cpp
  pmp::Face f;
  ...
  domain_ids[f] = 2;
```

### Inspect the mesh
```cpp
  vm::MeshInspectionErrors errors;
  bool is_mesh_ok = vm::inspect_mesh(in_mesh, vm::MeshInspection::Adjacency, errors);
  if(!is_mesh_ok) {
    std::cerr << "\nInput mesh failed inspection. \n";
    for(auto& e:errors)
      std::cerr << e << "\n";
    throw std::runtime_error("input mesh failed inspection tests ");
  }
```
Though not essential to check, vemesh implements a few checks on the mesh in the `vm::inspect_mesh` routine. 
This is especially useful if the input mesh is generated by a non-standard source.  
The checks on the mesh only constitute necessary (not sufficient) conditions required of the mesh.  
For convenience, vemesh provides two levels of checks. These are enumerated in `vm::MeshInspection`:
- `vm::MeshInspection::FaceGeometry` checks that each polygon in the mesh is valid and simple (as defined by Boost.Geometry).
- `vm::MeshInspection::Adjacency` additionally checks that neighboring faces intersect only along a common edge.   
It is of course possible to devise further checks. But the inspection becomes more expensive and is unlikely to be practical.  
In case of errors, the routine returns detailed information through an instance of `vm::MeshInspectionErrors`. 
The `vm::inspect_mesh` routine is expected to be useful as a debugging tool. It is not meant for production codes.  


### Algorithmic options
```cpp
  const double qepsilon = 0.2; 
  const double qfactor = 1.2;
```

The parameter `qepsilon`, in the range [0,1], defines the threshold to
identify faces of poor quality.  The agglomerate() method of the
vm::MeshOptimizer class used in this example tags faces whose
qualities fall below this threshold and attempts to agglomerate them
with neighbors if the result is favorable.  
Choosing a smaller value will agglomerate fewer faces, and vice versa.  

The parameter `qfactor`, assumed to be larger than 1, specifies the
condition to accept an agglomerated face. If \f$f,g\f$ are
agglomerable neighbors and say that quality of \f$f\f$ is poorer than
\f$g\$, i.e., \f$Q(f)<Q(g)\f$. Then the agglomerated face \f$fg\f$ is
considered only of $Q(fg)>{\rm qfactor}\times Q(f)\f$.  
This criterion prevents over-agglomeration, thus avoiding faces with
large number of vertices.  
Choosing a larger value with likely result in fewer successful
agglomerations. 


### Face quality
```cpp
	const auto face_quality_metric = vm::quality::vem_stability_ratio
    vm::QualityEvaluator QE(face_quality_metric);
```
vemesh enables users to define the metric for evaluating face qualities, see @ref quality.  
Two specific examples are provided with the library:   
- vm::quality::vem_stability_ratio: uses the ratio of extreme eigenvalues of
  the element-level stiffness matrix in the VEM to define element
  quality in a shape-agnostic manner  
  
This example uses the stability ratio.  

The vm::QualityEvaluator class provides different interfaces to
evaluate face/vertex qualities.  

Stored qualities are intended purely for diagnostics and output, not
for driving optimization.  

### Mesh optimizer
```cpp
	vm::MeshOptimizer optimizer(in_mesh);
   auto& mesh = optimizer.get_mesh();
```	
The class vm::MeshOptimizer implements element agglomeration and vertex relaxation functionalities in the library. 

It takes an instance of the mesh to be improved at construction and makes a copy. All operations on the mesh executed by the optimizer are performed on this copy. The mesh maintained by the optimizer can be immutably  using the `vm::MeshOptimizer::get_mesh()` method.

### Face quality evaluation
```cpp
   optimizer.evaluate_face_qualities(QE, vm::Face_Quality_Tag);
   vm::write_vtk(mesh, outdir+"/input_mesh.vtk");
   vm::write_face_quality_vector(mesh, outdir+"/qvec-input.dat");
```
The vm::MeshOptimizer class evaluates qualities of faces using the
vm::MeshOptimizer::evaluate_face_qualities method. The evaluated
qualities are stored as a face property in the mesh using the tag provided. In this example, we use the *default* tag
`vm::Face_Quality_Tag = "face_quality"`.   
Access the evaluated face qualities using the same tag, as:
```cpp
auto face_qualities = mesh.get_face_property<double>(vm::Face_Quality_Tag);
```

It is possible to store  face qualities evaluated using multiple
metrics in a mesh, simply by providing different quality evaluator
instances, and corresponding property tags.   
Note, however, that mesh \ref io "I/O" functions only look for the default tags
given by `vm::Face_Quality_Tag` when saving meshes to files.

The face qualities computed and stored in the mesh are **never** used
or accessed during mesh improvement. The agglomerate and relaxation
routines of vm::MeshOptimizer evaluate all qualities on the fly, using
the instance of the vm::QualityEvaluator object provided.

### Callback
```cpp
  vm::ProgressCallback callback =
    [outdir](const vm::ProgressInfo& info, 
	         const pmp::SurfaceMesh &mesh, 
			 const vm::MeshOptimizer &optimizer) {
    vm::write_vtk(mesh, outdir+"/mesh-"+std::to_string(info.num_completed)+".vtk");
    return true; };
```
The agglomerate method of vm::MeshOptimizer accepts a callback routine of type `vm::ProgressCallback`.  
The callback is invoked after each successful mesh update (and not
after every candidate face is considered).  
Thus, the callback provides a useful way of monitoring progress. It
can also be helpful debugging tool.  
If the callback returns false, the agglomeration procedure is aborted early.  

This example defines a callback to save the updated mesh after each
successful agglomeration.
Naturally, this results in frequent mesh outputs, and should therefore
be used only with small input meshes, if at all.
The meshes saved this way help visualize the agglomeration operation.  


### Element agglomeration
```cpp  
    int num_agg = optimizer.agglomerate(QE, qepsilon, qfactor, callback);
    std::cout << "Agglomerated " << num_agg << " faces " << std::flush;
```
The agglomerate operation is invoked with the specified quality evaluator, algorithmic parameters, and the callback.   
Internally:
- The agglomerate() method maintains a priority queue of faces ordered
such that the poorest quality face appears at the front of the queue. 
- The method chooses the optimal agglomerable neighbor to merge a face
with, so that each agglomeration operation achieves maximal
improvement.
- The method dynamically re-evaluates face qualities which may change during
the course of agglomeration. In particular, qualities stored in the mesh
are never accessed. 
- The method maintains a valid mesh at all times.
- It is possible that a face is agglomerated more than once, for
  instance, if it is adjacent to multiple neighbors of poor quality.
- It is also possible that a candidate face is not agglomerated,
either because it does not have an agglomerable neighbor, or the
resulting agglomerated face's quality is not sufficiently improvement.

It is common for only a small fraction of faces to be successfully
agglomerated, especially when starting from a reasonably good mesh.

The vm::MeshOptimizer::agglomerate method used here returns the number
of faces successfully merged. It can be used to evaluate the need for
further agglomeration, for example.

The vm::MeshOptimizer class provides two more overloaded relaxation
methods. They provide more control over faces to merge.

### Quality vector
```cpp
    vm::write_face_quality_vector(mesh, outdir+"/qvec-input.dat");
	...
	vm::write_face_quality_vector(mesh, outdir+"/qvec-output.dat");
```
In addition to saving face qualities, we also save the
*quality vector* of the input and output meshes.   
The mesh quality vector is a sorted list of face qualities. It
reveals a meaningful and monotonic sense in which the mesh quality
improves after each mesh update, see \ref userguide "User Guide".  
The quality vector allows a global comparison of meshes by ordering faces from worst to best and comparing these ordered values.

The first column of the saved file is an index, and the second is the
face quality. The length of the vector is hence equal to the number of
faces in the mesh. In particular, since the number of faces in the
mesh decreases with each successful the length of the quality vector
reduces as well.  
Nevertheless, the quality \f$q^{\rm out}_{n\times 1}\f$ of the output
mesh is better than the quality \f$q^{\rm in}_{m\times 1}\f$ 
of the input mesh in the sense that  
\f[ q^{\rm out}_i > q^{\rm in}_i~\text{for each}~i<\arg\min_j q^{\rm
out}_j = q^{\rm in}_j.\f] Visually, the curve representing the output
mesh's quality lies *above* that of the input mesh until their first
point of intersection.
