
\page tutorial_vertex_relaxation Vertex relaxation

This tutorial demonstrates using vemesh to relax vertices to improve element qualities in a polygonal mesh.  
Vertex relaxation perturbs vertices to more favorable locations by relying on the notion of vertex qualities.  
As discussed in @userguide, vertex qualities are defined implicitly in terms of face qualities in the mesh.  
Vertex relaxation leaves the topology of the mesh unchanged; just the locations of vertices are adjusted.  

**Overview:**  
- Load a polygonal mesh and identify constrained vertices (boundary or interface).
- Choose a face-based quality metric and define the corresponding vertex quality.
- Identify relaxable vertices whose quality falls below a prescribed threshold.
- Iteratively perturb each candidate vertex by sampling feasible nearby positions:
  - accept a perturbation only if it improves vertex quality and preserves mesh validity.
- Update the mesh while keeping the topology unchanged.
- Output the relaxed mesh and compare input/output quality vectors.

## Explanation

### Load the mesh
```cpp
const std::string meshfile = "sample_data/sorgente/mesh3_20.off";
... 
pmp::SurfaceMesh in_mesh = vm::read_off(meshfile);

```
vemesh provides readers for OFF and VTK file formats, see @ref io.  
The mesh loaded this way has 
- an integer-valued face property `domain_id`, initialized to a default value of 1.
- an integer-valued vertex property `interface_id`, initialized to a default value of -1.

Only vertices 
- not lying on the boundary of the mesh, and
- with `interface_id` equal to -1 
can be relaxed. Vertices lying on the boundary or an interface are considered to be *constrained*, and are therefore not relaxable.

The `interface_id` can be accessed as:
```cpp
  auto& interface_ids = in_mesh.get_vertex_property<int>("interface_id"); 
```
and can be modified:
```cpp
  pmp::Vertex v;
  ...
  interface_ids[v] = 2;  // e.g., v lies on interface #2
```

### Inspect the mesh
```cpp
  vm::MeshInspectionErrors errors;
  bool is_mesh_ok = vm::inspect_mesh(in_mesh, vm::MeshInspection::Adjacency, errors);
  if(!is_mesh_ok) {
    std::cerr << "\nInput mesh failed inspection. \n";
    for(auto& e:errors)
      std::cerr << e << "\n";
    throw std::runtime_error("input mesh failed inspection tests ");
  }
```
Though not essential to check, vemesh implements a few checks on the mesh in the `vm::inspect_mesh` routine. 
This is especially useful if the input mesh is generated by a non-standard source.  
The checks on the mesh only constitute necessary (not sufficient) conditions required of the mesh.  
For convenience, vemesh provides two levels of checks. These are enumerated in `vm::MeshInspection`:
- `vm::MeshInspection::FaceGeometry` checks that each polygon in the mesh is valid and simple (as defined by Boost.Geometry).
- `vm::MeshInspection::Adjacency` additionally checks that neighboring faces intersect only along a common edge.   
It is of course possible to devise further checks. But the inspection becomes more expensive and is unlikely to be practical.  
In case of errors, the routine returns detailed information through an instance of `vm::MeshInspectionErrors`. 
The `vm::inspect_mesh` routine is expected to be useful as a debugging tool. It is not meant for production codes.  


### Algorithmic options
```cpp
  const double qepsilon = 0.2; 
  const double num_samples = 10;
  ```

The parameter `qepsilon`, in the range [0,1], defines the threshold to identify vertices of poor quality. The relax() method of the vm::MeshOptimizer class used in this example tags vertices whose qualities fall below this threshold and perturbs them to more
favorable locations in ascending order of quality.  
Choosing a smaller value will relax fewer vertices, and vice versa.  
Only vertices with `interface_id` equal to -1, and not lying on the boundary  are shortlisted for relaxation. 

The parameter `num_samples`, assumed to be larger than 1, specifies the
number of randomly generated candidate sample points that are
inspected to relocate each vertex. In general:  
- only a fraction of these sample points are feasible, i.e.,
result in a valid mesh without self-intersections or degenerate faces.
- a larger choice for the number of samples will likely yield more
  improvement, but at the expense of additional computations.

### Vertex quality
```cpp
	const auto face_quality_metric = vm::quality::geom_shape;
    vm::QualityEvaluator QE(face_quality_metric);
```
vemesh enables users to define the metric for evaluating face qualities, see @ref quality.  
The vertex quality is defined implicitly using this metric, see @userguide.

Two specific examples are provided with the library:   
- vm::quality::vem_stability_ratio: uses the ratio of extreme eigenvalues of
  the element-level stiffness matrix in the VEM to define element
  quality in a shape-agnostic manner  
- vm::quality::geom_shape: defines a geometric measure of polygon quality. It uses a non-dimensional ratio of the area and the
  squared-perimeter, so that more regular polygons are assigned a
  better quality closer to 1.
  
This example uses the geometric measure for the quality metric.

The vm::QualityEvaluator class provides different interfaces to evaluate face/vertex qualities.

### Mesh optimizer
```cpp
	vm::MeshOptimizer optimizer(in_mesh);
   auto& mesh = optimizer.get_mesh();
```	
The class vm::MeshOptimizer implements element agglomeration and vertex relaxation functionalities in the library. 

It takes an instance of the mesh to be improved at construction and makes a copy. All operations on the mesh executed by the optimizer are performed on this copy. The mesh maintained by the optimizer can be immutably  using the `vm::MeshOptimizer::get_mesh()` method.

### Face/vertex quality evaluation
```cpp
   optimizer.evaluate_face_qualities(QE, vm::Face_Quality_Tag);
   optimizer.evaluate_vertex_qualities(vm::Face_Quality_Tag, vm::Vertex_Quality_Tag);
   vm::write_vtk(mesh, outdir+"/input_mesh.vtk");
   vm::write_face_quality_vector(mesh, outdir+"/qvec-input.dat");
```
The vm::MeshOptimizer class evaluates qualities of faces using the
vm::MeshOptimizer::evaluate_face_qualities method. The evaluated
qualities are stored as a face property in the mesh using the tag
provided. In this example, we use the *default* tag
'vm::Face_Quality_Tag = "face_quality"`. Access the evaluated face qualities using the same tag, as:
```cpp
auto face_qualities = mesh.get_face_property<double>(vm::Face_Quality_Tag);
```

Since vertex qualities are defined using face qualities, the
`evaluate_vertex_qualities()` method takes the property tag storing
face qualities in the mesh as input. No quality evaluations are performed. Instead, 
face qualities are accessed from the tag provided. Vertex qualities are saved under the specified vertex property tag, 
which, in this case, is the *default tag* `vm::Vertex_Quality_Tag="vertex_quality"`. 
Access the evaluated vertex qualities as:
```cpp
auto vertex_qualities = mesh.get_vertex_property<double>(vm::Vertex_Quality_Tag);
```

It is possible to evaluate and store multiple face quality metrics, and corresponding vertex quality metrics in a mesh. 
Note, however, that mesh @io functions only look for the default tags given by `vm::Face_Quality_Tag` 
and `vm::Vertex_Quality_Tag` when saving meshes to files.

The face and vertex qualities computed and stored in the mesh this way are **not** used or accessed during mesh improvement. The agglomerate and relaxation routines of vm::MeshOptimizer evaluate all qualities on the fly, using the instance of the vm::QualityEvaluator object provided.

### Callback
```cpp
  vm::ProgressCallback callback =
    [outdir](const vm::ProgressInfo& info, 
	         const pmp::SurfaceMesh &mesh, 
			 const vm::MeshOptimizer &optimizer) {
    vm::write_vtk(mesh, outdir+"/mesh-"+std::to_string(info.num_completed)+".vtk");
    return true; };
```
The relaxation method of vm::MeshOptimizer accepts a callback routine of type `vm::ProgressCallback`.  
The callback is invoked after each successful vertex update (and not
after every candidate vertex is considered).  
Thus, the callback provides a useful way of monitoring progress. It
can also be helpful debugging tool.  
If the callback returns false, the relaxation procedure is aborted early.  

This example defines a callback to save the updated mesh after each vertex perturbation. Obviously, this results in mesh outputs with high frequency, and should be used only with small input meshes, if at all. The meshes saved this way help visualize the relaxation operation.  


### Vertex relaxation
```cpp  
  int num_relaxed = optimizer.relax(QE, qepsilon, num_samples, callback);
  std::cout << "Relaxed " << num_relaxed << " vertices " << std::flush;
```
The relaxation operation is invoked with the specified quality evaluator, algorithmic parameters, and the callback.   
Internally:
- The relax() method maintains a priority queue of vertices ordered such that the poorest vertex appears at the front
of the queue. 
- The method ensures that each vertex is relaxed at most once.
- It dynamically re-evaluates vertex qualities which may change during
the course of relaxation. In particular, qualities stored in the mesh
are never accessed.
- The method maintains a valid mesh at all times.

It is possible that a vertex marked for relaxation may not be
relocated. This can happen because:  
- the quality of a vertex can improve when a neighboring vertex is
  perturbed. 
- the generated sample points may not improve a vertex's quality,
  which is then left undisturbed.   
It is common for only a small fraction of vertices to be successfully relaxed, especially when starting from a reasonably good mesh.

The vm::MeshOptimizer::relax method used here returns the number of
vertice successfully relaxed. It can be used to  evaluate the need for further relaxation, for example.

The vm::MeshOptimizer  class provides two more overloaded relaxation methods. They provide more control over vertices to relax. 

### Quality vector
```cpp
    vm::write_vertex_quality_vector(mesh, outdir+"/qvec-input.dat");
	...
	vm::write_vertex_quality_vector(mesh, outdir+"/qvec-output.dat");
```
In addition to saving vertex qualities , we also save the
*quality vector* of the input and output meshes.   
The mesh quality vector is a sorted list of vertex qualities. It
reveals a meaningful and monotonic sense in which the mesh quality
improves after each mesh update, see @userguide.  
The quality vector allows a global comparison of meshes by ordering vertices from worst to best and comparing these ordered values.

The first column of the saved file is an index, and the second is the vertex quality. The length of the vector is hence equal to the number of vertices in the mesh. In particular, since the number of vertices in the mesh remains unchanged during relaxation, the length of the quality vector remains a constant.  The quality \f$q^{\rm out}_{n\times 1}\f$ of the output mesh is better than the quality \f$q^{\rm in}_{m\times 1}\f$ of the input mesh in the sense that  
\f[ q^{\rm out}_i > q^{\rm in}_i~\text{for each}~i<\arg\min_j q^{\rm
out}_j = q^{\rm in}_j.\f] Visually, the curve representing the output
mesh's quality lies *above* that of the input mesh until their first
point of intersection.
